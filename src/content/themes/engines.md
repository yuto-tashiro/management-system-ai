## 変換ラダー：今月の売上は、どの段から生まれているか

フリーランスは「専門性 × 自分の時間 × 自分の評判 → 売上」で成り立ちます。法人として事業を育てるには、自分の知識を、**自分以外でも価値を生む構造**へ変換していく必要があります。

**Labor（労働）→ Expertise（専門性）→ Service（サービス）→ Product（商品）→ System（仕組み）→ Organization（組織能力）→ Asset（事業資産）**

この階段を一段ずつきれいに上がれることは、ほとんどありません。型をつくりかけては次の案件で崩れ、プロダクトをつくっては現場に戻る。行き来しながら進むものです。ですから、この階段は「上がりきるもの」ではなく、**今月の売上がどの段から生まれているかを確かめる物差し**として使います。売上の100％が自分の稼働から生まれているなら、それは法人としてはかなり脆い状態です。

## 5つの事業エンジン

| エンジン | 主な価値 | 具体例 | 注意 |
| --- | --- | --- | --- |
| High-ticket ToC | 深い個別価値とケースの蓄積 | 高単価のコンディショニング、個別伴走 | 稼働に依存しやすい。学習価値の高い案件に絞る |
| ToB | 大きな課題への適用 | 企業支援、研修、共同研究、コンサルティング | 身体の問題を企業の言葉へ翻訳する |
| Media / Education | 知識の1対N化 | 記事、講座、研修教材、コミュニティ | 商品であると同時に、仲間と出会う場所 |
| Code / Product | 判断の複製 | アプリ、評価ツール、AI支援、ダッシュボード | 作れることと提供してよいことを分ける |
| System / IP | 再現性と組織化 | 認定制度、プロトコル、ライセンス、データベース | 基準に責任を持つ |

全部を同時に行う必要はありません。むしろ資源を分散させすぎないことが大切です。ただし、法人として発展させるなら、**経営者の時間を直接売る以外のエンジンを最低一つ**持つことを目指します。

### エンジンを増やす順番

1. High-ticket ToC または ToB で、キャッシュと実績をつくる
2. その過程のケースを Media / Education に変える（同時に組織知が整理される）
3. 繰り返し行う判断を Code / Product に変える
4. 品質を担保する仕組みを System / IP として固める

**後ろのエンジンほど、前のエンジンの蓄積がないとつくれません。** 現場のケースがないまま教材をつくると一般論になり、方法論が固まらないままアプリをつくると何を実装すべきか決まらず、実績がないまま認定制度をつくっても誰も参加しません。

### 継続契約になりやすい条件

ToBで継続契約になりやすいのは、「**今月の売上**」と「**3年後の可能性**」の両方に効いているときだ、という仮説があります<a class="ev-badge ev-hypothesis" href="/about/#evidence-hypothesis">HILUCOの実務仮説</a>。専門職の強み（エビデンス、効果検証）は「3年後の可能性」側に寄りがちなので、販売支援・販路の紹介・広告への根拠提供など、売上側にも接続する手段を一つ持っておくと契約が安定します。

## 三層構造：活動ごとに収益の基準を変える

一人の専門家の活動を、三つの層に分けて考えます。

| 層 | 蓄積するもの | 収益の基準 |
| --- | --- | --- |
| 思想の層 | なぜやるのか（問い、論考、社会像） | 短期の売上で評価しない |
| 実践者の層 | 誰と一緒にやるのか（コミュニティ、教材、仲間） | 公共財として黒字トントンでもよい |
| 事業の層 | 何をどう提供し、いくらで成立させるか | 利益をつくる |

一つの法人・一つの財布にすべてを詰め込むと、「社会的意義はあるが儲からない活動」と「儲かるが思想が薄い仕事」が衝突し、たいてい短期の売上が勝って思想の層が削られます。層を分けておくと、「この活動は黒字トントンでよい」「この活動で利益をつくる」「この活動は将来の資産のための先行投資」と、別々の基準で判断できます。

ただし、**層を分けることと、名義を分散させることは違います**。名義は集約し、層は分ける。

## 時間の同期が必要な収益／必要ない収益

| 種類 | 例 | 役割 |
| --- | --- | --- |
| 同期型 | 臨床、セミナー、コンサルの会議、個別伴走 | 現場と知見を保つ。非同期型への投資の原資になる |
| 非同期型 | 教材・コンテンツ、アプリやツールの利用料、ライセンス・認定料、紹介・販売代行、データや知見の提供 | 時間の制約を外す |

目指すのは、同期型をゼロにすることではなく、**同期型で現場と知見を保ちながら、非同期型で時間の制約を外していく**バランスです。非同期型をつくるには、たいてい先に時間を投資する必要があります。

## 3つの収益で案件を評価する

| 収益 | 問い | 主基準にする活動 |
| --- | --- | --- |
| Cash Return | 今回いくらの利益が生まれるか | 利益をつくる活動 |
| Learning Return | 新しい知識・ケース・データ・能力が得られるか | 将来の資産をつくる活動 |
| Relationship Return | 良い顧客・協力者・市場との関係が深まるか | 公共財として維持する活動 |

案件を受ける前に、3つを一言ずつ書いておくだけで十分です。判断の回数を減らすこと自体が、小さな会社にとっては経営資源の節約になります。

## 月次で確かめる8つの指標

| ループ | 指標の例 |
| --- | --- |
| SEARCH | 新しく捉えた社会変化・顧客変化の数 |
| POSITION | 自社の強みが活きる案件の比率 |
| EXPERIMENT | 実施した小さな検証と、得られた学び |
| SERVE | 継続率、成果、顧客からの質的フィードバック |
| LEARN | 追加・更新したケース、原則、プロトコル |
| TRUST | 紹介、指名、再依頼、外部からの評価 |
| SYSTEMIZE | 標準化・自動化できた業務、経営者以外が提供した割合 |
| RENEW | 探索に使った時間と、事業の見直し内容 |

すべてを厳密に数値化する必要はありません。月に一度、「会社は売上以外に何を蓄積したか？」と問い直すだけでも、意思決定は変わります。
